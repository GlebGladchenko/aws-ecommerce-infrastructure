# Security

> **Status:** controls for the network and compute layers are implemented;
> the rest are planned and documented here as each template lands.

## Identity and access

- **No long-lived AWS keys.** GitHub Actions authenticates with
  [GitHub OIDC](https://docs.github.com/en/actions/security-for-github-actions/security-hardening-your-deployments/configuring-openid-connect-in-amazon-web-services)
  and `sts:AssumeRoleWithWebIdentity`.
- **Deployment role trust policy** is restricted to this repository and to the
  GitHub Environment being deployed, e.g.
  `token.actions.githubusercontent.com:sub = repo:<owner>/aws-ecommerce-infrastructure:environment:prod`.
- **Bootstrap resources** (the OIDC identity provider, the deploy role and the
  template artifact bucket) are created once per account, outside the main stack,
  because a stack cannot create the role that deploys it. TODO: add a
  `bootstrap/` template for these.
- **Runtime role** (`security/iam.yml`): each permission is scoped to a specific
  resource ARN. Implemented: image pull (no push) on the `<project>-<env>-api`
  repository, `CreateLogStream`/`PutLogEvents` on the app log group,
  `CompleteLifecycleAction` on the app Auto Scaling group (readiness hook), and
  `AmazonSSMManagedInstanceCore` for Session Manager. Planned: secrets and the
  assets bucket. The only unscoped action is `ecr:GetAuthorizationToken`, which
  AWS does not support scoping.
- **Instance metadata:** IMDSv2 only, hop limit 1, so the container cannot reach
  the metadata service or the instance role credentials.
- **No SSH.** Instances have no key pair and no port 22; administrators use
  SSM Session Manager, which is IAM-controlled and logged.

## Network

- Only the ALB and NAT Gateways live in public subnets. Instances have no
  public IP; with `NatGatewayMode=none` the app tier has no internet route at
  all and reaches AWS APIs through VPC endpoints, whose security group admits
  only 443 from the app security group.
- The ALB security group accepts traffic only from the CloudFront origin-facing
  managed prefix list; a secret origin header blocks other CloudFront distributions
  (planned). For testing before CloudFront exists, `AlbTestIngressCidr` adds one
  optional rule for a single CIDR; it is passed at deploy time and never
  committed.
- App instances accept traffic only from the ALB security group, on
  `AppContainerPort` (8080).
- The app trusts `X-Forwarded-For`/`-Proto` only from
  `UVICORN_FORWARDED_ALLOW_IPS`. The image default is loopback only; on EC2 it is
  set to the VPC CIDR (the ALB's addresses change as it scales), never `*`.
  Together with the app security group, this means only the ALB can set the
  client IP and scheme the app sees.
- The database accepts port 5432 only from the app security group, and the data
  subnets have no route to the internet.
- VPC Flow Logs are enabled.

## Data protection

| Data                   | At rest                         | In transit                         |
|------------------------|---------------------------------|------------------------------------|
| RDS PostgreSQL         | KMS (customer managed key)      | `rds.force_ssl = 1`                |
| S3 buckets             | SSE-S3 / SSE-KMS                | bucket policy denies non-TLS       |
| EBS volumes            | encrypted gp3                   | -                                  |
| Secrets Manager        | customer managed KMS key        | TLS (AWS API)                      |
| SNS alarm topic        | customer managed KMS key        | TLS                                |
| Viewer traffic         | -                               | CloudFront TLSv1.2_2021 minimum    |
| CloudFront -> ALB      | -                               | HTTPS-only origin protocol         |

S3 buckets block all public access; assets are reachable only through CloudFront
Origin Access Control.

## Secrets management

- **Nothing secret is committed.** `environments/*/parameters.json` holds only
  non-sensitive configuration, and `.gitignore` excludes credentials, keys and
  `.env` files.
- The database master password is created and rotated by RDS
  (`ManageMasterUserPassword`), stored in Secrets Manager.
- Application secrets are generated by Secrets Manager (`GenerateSecretString`).
- Instances fetch secrets at boot through their IAM role; secrets are never
  placed in user data, AMIs or container images.

## Edge protection

AWS WAF on CloudFront with the AWS managed IP reputation, Common, Known Bad
Inputs and SQLi rule groups plus a per-IP rate limit. WAF logs redact the
`Authorization` and `Cookie` headers.

## Detection and audit

- CloudTrail (planned `monitoring/cloudtrail.yml`): multi-region, log file
  validation, KMS-encrypted.
- CloudWatch alarms for 5xx rates, unhealthy hosts and database health, routed
  to an encrypted SNS topic.
- ECR scan on push.

## CI/CD safeguards

- Workflows default to `permissions: contents: read`; only jobs that assume an
  AWS role get `id-token: write`.
- Deployment is manual (`workflow_dispatch`), disabled until
  `INFRA_DEPLOY_ENABLED=true`, creates a change set for review by default, and
  prod is gated by GitHub Environment required reviewers.
